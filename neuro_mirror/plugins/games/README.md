# Игровые модули

`catalog.py` содержит утверждённую матрицу форм. Первый домен в каждой записи —
ведущий. `registry.py` автоматически находит реализованные игры, поэтому ручной
импорт в `app/runtime.py` не требуется.

## Как добавить реализацию игры

1. Выбрать уникальный код формата `GM-...`. Если формы нет в исходном
   `catalog.py`, задать полный `game_definition` внутри класса плагина.
2. Скопировать `_template` в папку с любым понятным Python-именем, например
   `pair_cards`. Связь с определением задаётся обязательным `game_code`
   внутри класса плагина, а не названием папки.
3. Реализовать `plugin.py`, `stimuli.py` и браузерный `web.js`.
4. Чистый расчёт метрик положить в `neuro_mirror/screening/gm01_scoring.py`.
5. Добавить проверки сценария, журнала проб и расчёта.

Папки, имя которых начинается с `_`, считаются черновиками и не загружаются.
Реестр требует ровно один класс `Plugin` в `plugin.py`. Код игры задаёт общие
темы событий и маршруты `/api/games/{code}/start` и `/answer`.

Каждый ответ должен сохранять первичную пробу: стимул, ответ, время и
техническую валидность. Рассчитанные метрики не заменяют первичные события.
