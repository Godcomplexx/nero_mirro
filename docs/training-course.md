# Тренировочный курс: как он формируется и работает

Описание по документу «Методика подбора и оценки тренировочного курса»,
черновик v2 от 08.10.2026, проект для утверждения. Входные данные курса
описаны в «Методологии скрининга», редакция 2.0 от 08.10.2026.

Обе методики ещё не утверждены. Значения с пометкой «предложение» —
предложения методики, а не утверждённые нормативы. В программе они заданы
константами в одном месте, чтобы после утверждения поменять их без переделки:
пороги перехода — `neuro_mirror/screening/difficulty_policy.py`, этапы и
стимульные наборы — `neuro_mirror/screening/training_course.py`.

У каждого правила указано состояние в программе:

- **реализовано** — работает так, как написано;
- **частично** — работает, но не полностью или иначе;
- **не реализовано** — в программе этого пока нет.

## 1. Место курса в цикле наблюдения

Курс стоит между входным и выходным скринингом:

1. **Входной скрининг** — подготовка сессии, базовый скрининг (видеоанализ и
   HADS) и расширенный скрининг (аудио-MoCA, затем ситуационная задача).
2. **Курс тренировок** — 12 занятий.
3. **Выходной скрининг** — те же пробы в том же порядке. Ситуационная задача
   проводится на парном нарративе, а не на том, что был на входе.

Динамику когнитивного статуса показывает только выходной скрининг. Результаты
тренировок отражают выполнение упражнений.

| Правило | Состояние |
|---|---|
| Курс открывается после завершённого входного скрининга, до этого тренировка заблокирована с текстовой причиной | реализовано |
| После 12-го занятия курс закрывается, следующий шаг — выходной скрининг | реализовано: тренировка отвечает «Курс из 12 занятий пройден…» и предлагает пройти когнитивный тест. Результат теста, полученный после закрытия курса, начинает новый курс |
| Ситуационная задача | не реализовано: методика модуля на утверждении |

## 2. Вход курса

Модуль тренировок получает от агрегатора результат аудио-MoCA по четырём
доменам: память 0–5, внимание 0–5, речь 0–3, абстракция 0–2, сумма 15.

Из баллов получаются два показателя с разным назначением:

- **недобор** `U = M − S` — по нему распределяются задания;
- **нормированный дефицит** `D = (M − S) / M` — идёт в отчёт специалиста,
  чтобы сравнивать домены с разными максимумами.

Здесь `S` — балл пользователя, `M` — максимум домена.

Недобор фиксируется по **входному** скринингу на весь курс. Результаты
тренировок его не пересчитывают: иначе тренировка подменила бы обследование.

| Правило | Состояние |
|---|---|
| Недобор и нормированный дефицит по четырём доменам | реализовано |
| Недобор фиксируется по входному скринингу на весь курс | реализовано: профиль запоминается при открытии курса; тест, пройденный во время курса, его не меняет |
| Домен с отметкой «низкая достоверность» (2 и более нераспознанных ответа) получает недобор 0 до подтверждения специалистом | не реализовано: отметки достоверности по домену нет |
| Контекст HADS: при 8 баллах и выше по любой подшкале — отметка рядом с результатом аудио-MoCA | не реализовано |

Исполнительные функции относятся к домену «Абстракция»: аудио-MoCA не даёт по
ним отдельного балла, поэтому доменов четыре.

## 3. Структура курса

- 12 занятий по 10 заданий, всего 120 прохождений.
- Одно задание — около 5 минут, занятие — около 50 минут.
- Частота — 2 занятия в неделю, курс — около 6 недель.
- В каждом занятии 4 обязательных задания, по одному на домен, и 6
  дополнительных — по недобору.

| Правило | Состояние |
|---|---|
| Занятие из 10 заданий, длина задаётся параметром, не меньше 4 | реализовано |
| Курс из 12 занятий с номером занятия | реализовано |
| Частота 2 занятия в неделю | не контролируется: следующее занятие доступно сразу после завершения предыдущего |

## 4. Распределение заданий по доменам

1. Каждый домен получает по одному заданию — 4 из 10.
2. Остальные 6 раздаются по одному. Каждое следующее получает домен с
   наибольшим отношением `U / n`, где `n` — сколько заданий у домена уже есть.
3. Потолок — не больше половины занятия на один домен. Домен, достигший
   потолка, из раздачи выбывает.
4. При равенстве отношений первым идёт домен, у которого меньше заданий.
   Затем — тот, что реже встречался в курсе. При полном равенстве —
   фиксированный порядок: память, внимание, речь, абстракция.
5. Сравнение точное, перекрёстным умножением, без округления.

Контрольные случаи из методики. Все шесть проверены на коде и совпадают:

| Случай | Недобор: память / внимание / речь / абстракция | Длина | Результат |
|---|---|---|---|
| Пример 1 | 2 / 1 / 1 / 1 | 10 | 4 / 2 / 2 / 2 |
| Пример 2 | 3 / 1 / 0 / 1 | 10 | 5 / 2 / 1 / 2 |
| Недобора нет | 0 / 0 / 0 / 0 | 10 | 3 / 3 / 2 / 2 |
| Потолок памяти | 5 / 0 / 0 / 0 | 10 | 5 / 2 / 2 / 1 |
| Только абстракция | 0 / 0 / 0 / 2 | 10 | 2 / 2 / 1 / 5 |
| Длина 9 | 5 / 0 / 0 / 0 | 9 | 4 / 2 / 2 / 1 |

| Правило | Состояние |
|---|---|
| Обязательный минимум, пошаговая раздача, потолок | реализовано |
| Равенство: меньше заданий, затем фиксированный порядок | реализовано |
| Равенство: домен, реже встречавшийся в курсе | реализовано: при отсутствии недобора тройки переходят от занятия к занятию (3/3/2/2, затем 2/2/3/3) |

## 5. Этапы курса

| Занятия | Этап | Назначение | Уровни |
|---|---|---|---|
| 1–2 | Калибровка | Понимание инструкций, работа интерфейса, знакомство с формами | Уровень 1 у всех форм |
| 3–5 | Освоение | Стабилизация, основная нагрузка на приоритетные домены, накопление динамики по каждой форме | Уровень 1 у всех форм; уровни не меняются |
| 6 | Присвоение уровней и промежуточный контроль | Уровни присваиваются по динамике занятий 3–5; проверка устойчивости на новом стимульном наборе | Уровень 1 или 2 |
| 7–12 | Адаптивная тренировка | Удержание успешности 70–85% и рост сложности; в 12-м занятии — стимульный набор 3 для сравнения с 6-м | Уровни меняются по итогам предыдущего занятия, до уровня 3 |

После 12-го занятия собираются итоговые показатели и проводится выходной
скрининг.

**Состояние: реализовано.** Номер занятия задаёт этап, стимульный набор и то,
меняются ли уровни. Этап и номер приходят в ответе
`GET /api/training/session` (`course.session_number`, `course.stage`) и
показываются на экране тренировки: «Занятие 3 из 12 · Освоение».

## 6. Уровень сложности

Уровень ведётся отдельно для каждой формы у каждого пользователя. Переход по
одной форме не меняет уровни других форм того же домена.

### 6.1. Какие прохождения учитываются

| Статус завершения | Учитывается для адаптации |
|---|---|
| completed_success — правильный ответ до исчерпания времени и попыток | да |
| completed_unsuccessful — попытки исчерпаны | да |
| timeout — лимит времени | да |
| abandoned — пользователь прервал | нет: нулём не считается |
| technical_invalid — техническая проблема | нет |
| «не определено» — у формы нет показателей полноты | нет: форма идёт без адаптации |

Успешность хранится как числитель и знаменатель. Порог проверяется точно:
`правильные · 100 ≥ 85 · всего`.

В программе игра отдаёт «завершено» (`completed`), когда пройдены все пробы, и
«не завершено» (`incomplete`), когда задание кончилось раньше — по времени или
попыткам. Оба учитываются. Технически непригодное прохождение и прохождение
без признаков полноты не учитываются. Прерванное задание исхода не даёт и
получает в плане занятия статус `abandoned`.

### 6.2. Правило перехода

| Успешность прохождения | Условие | Действие при следующем показе формы |
|---|---|---|
| не меньше 0,85 | одно учитываемое прохождение | уровень +1 |
| от 0,50 до 0,85 | — | уровень сохраняется |
| меньше 0,50 | два учитываемых прохождения подряд | уровень −1 |

Счётчик «ниже 50% подряд» ведётся по форме и сбрасывается при любой смене
уровня. За один пересчёт уровень меняется не больше чем на один шаг.
Неучитываемые прохождения серию не прерывают и в неё не входят.

### 6.3. Когда применяется правило

1. **Занятия 1–5** — у всех форм уровень 1, уровни не меняются.
2. **Перед 6-м занятием** уровень присваивается по занятиям 3–5. Предложение:
   уровень 2, если сводная успешность формы за занятия 3–5 не ниже 0,85, а
   последнее прохождение не ниже 0,70. Иначе уровень 1. При сводной
   успешности ниже 0,50 форма получает отметку «трудная».
3. **Занятия 7–12** — уровни пересчитываются по итогам предыдущего занятия.
   Если форма в нём не показывалась, её уровень не меняется.
4. **После 12-го занятия** уровни не пересчитываются.

Граничные случаи (предложение): ниже 50% дважды подряд на уровне 1 — уровень
остаётся 1, форма получает отметку «трудная». 85% и выше на уровне 3 —
уровень остаётся 3, отметка «потолок».

### 6.4. Как это устроено в программе

**Состояние: реализовано.**

- Уровни не хранятся отдельно, а выводятся из прохождений курса при сборке
  каждого занятия (`training_course.form_states`). Сохранённое состояние не
  может разойтись с тем, что человек проходил.
- Сводная успешность за занятия 3–5 — сумма верных на сумму всех, а не
  среднее долей.
- Отметки «трудная» и «потолок» идут в план занятия (`flags`). Генератор
  выбирает отмеченные формы реже: только когда других форм домена нет.
- Каждый переход записывается в журнал: перед каким занятием, форма, с какого
  уровня на какой, по какой успешности. Переходы перед текущим занятием
  приходят в `level_changes` ответа `GET /api/training/session`, весь журнал —
  в `GET /api/training/course`.
- Свободная игра («Выбрать игру самому») в курс не входит и уровни не меняет.

## 7. Формы, готовые к адаптации

Уровни 1–3 заданы матрицей игр для 12 форм из 24. Остальные идут в
фиксированной конфигурации без адаптации.

| Домен | Формы с уровнями |
|---|---|
| Память | GM-01, 02, 03, 04, 06 |
| Внимание | GM-07, 09, 10 |
| Речь | GM-14 |
| Абстракция | GM-17, 18, 22 |

Значения уровней в программе совпадают с матрицей.

Показатель успешности для перехода — числитель и знаменатель:

| Форма | Показатель по методике | Верные / всего в программе |
|---|---|---|
| GM-01 | U08 — доля найденных пар | найденные пары / все пары |
| GM-02 | M08 — доля полностью верных серий | верные серии / все серии |
| GM-03 | U01 | верные пробы / все пробы |
| GM-04 | M07 | узнанные цели / все цели |
| GM-06 | M08 | верные серии / все серии |
| GM-07 | U01 | верные экраны / все экраны |
| GM-09 | A06 — доля правильно выбранных целей | выбранные цели / все цели |
| GM-10 | A07 — доля найденных отличий | найденные отличия / все отличия |
| GM-14 | U01 — слова, собранные с первой попытки | слова с первой попытки / все слова |
| GM-17 | U01 | верные пробы / все пробы |
| GM-18 | U01 — фрагменты, установленные с первой попытки | фрагменты, вставшие на место первым же перемещением / все перемещённые фрагменты |
| GM-22 | U03 — доля башен, собранных в целевую конфигурацию | собранные башни / все башни |

GM-02 раньше оценивалась по последней серии: ошибка на десятой серии давала
ноль. Теперь — по всем сериям прохождения, как в методике.

**Вопрос к методистам.** У GM-01 и GM-22 нет лимита времени, а задание
заканчивается только сборкой. Поэтому законченное прохождение всегда даёт
100%, и с 7-го занятия уровень этих форм растёт при каждом показе. Методика
отмечает, что лимит времени GM-01 и правила GM-22 ещё нужно утвердить.

| Правило | Состояние |
|---|---|
| 12 форм с уровнями, значения из матрицы | реализовано |
| Отметка fixed_config у форм без уровней | реализовано: у таких форм `adaptation: "fixed_config"` и пустой уровень |
| Показатель успешности по методике у всех 12 форм | реализовано |

## 8. Сборка занятия

### 8.1. Обязательные правила

1. Состав по доменам — по разделу 4, все четыре домена представлены.
2. Одна форма не повторяется дважды в одном занятии.
3. Тренировочные формы не копируют материалы аудио-MoCA (GM-11, 13, 16, 24).

### 8.2. Желательные правила, по убыванию веса

1. Не больше трёх подряд заданий с одинаковым типом ответа.
2. Не больше трёх подряд с одинаковой визуальной схемой выбора.
3. После сложного задания — более простое или другое по модальности.
4. Два задания одного домена не стоят подряд.
5. Модальности подачи чередуются.

### 8.3. Выбор формы внутри домена

По порядку приоритета, как в программе:

1. форма с уровнями сложности (формы без уровней берутся, когда домену не
   хватает адаптивных);
2. форма без отметок «трудная» и «потолок»;
3. механика, реже встречавшаяся в курсе;
4. форма, которой не было в прошлом занятии;
5. механика и модальность отличаются от предыдущего задания занятия;
6. меньше прошлых показов.

### 8.4. План занятия

План сохраняется при сборке: порядок, домены, формы, уровни, стимульные
наборы, зерно случайности, причины выбора. Перезагрузка страницы и возврат к
прерванному занятию берут сохранённый план. Хранится в
`runtime/deidentified/training_courses.json`.

### 8.5. Стимульные наборы

| Занятия | Набор |
|---|---|
| 1–2 | набор 1 |
| 3–5 | набор 2 |
| 6 | набор 3, ранее не показанный |
| 7–11 | наборы 1 и 2 по очереди |
| 12 | набор 3, для сравнения с 6-м |

Номер набора соответствует порядку наборов формы в матрице. У формы с одним
набором он показывается всегда, а различаться должно зерно случайности
«пользователь + форма + номер занятия».

| Правило | Состояние |
|---|---|
| Состав по доменам; форма не повторяется в занятии | реализовано |
| Два задания одного домена не стоят подряд | реализовано |
| Чередование механик и модальностей с предыдущим заданием | реализовано |
| Охват форм в калибровке, второе занятие — формы, которых не было в первом | реализовано |
| Первое задание калибровки — клик и зрительная подача | реализовано |
| Не больше трёх подряд с одинаковым типом ответа | не реализовано |
| После сложного задания — более простое | не реализовано |
| Первое и последнее задание — посильные (с 3-го занятия) | не реализовано |
| План занятия сохраняется при сборке | реализовано |
| Стимульные наборы по этапам курса | реализовано |
| Зерно случайности | частично: записывается в план и передаётся игре, но игры пока его не используют и перемешивают стимулы заново |

## 9. Ход занятия

- После каждого задания сохраняется контрольная точка.
- Задание заканчивается досрочно, по лимиту времени или по исчерпанию
  попыток. Затем — экран с нейтральной обратной связью и кнопкой «Следующее
  задание». Автоматического перехода нет.
- Кнопка «Пауза» доступна всегда. На паузе таймер останавливается, стимулы
  скрываются. Из паузы — «Продолжить» или «Завершить занятие».
- Прерванное задание получает статус abandoned: нулём не считается и в
  адаптацию не входит.
- Время паузы и время до нажатия «Следующее задание» не входят в активное
  время.
- Каждая пауза пишется в журнал.

| Правило | Состояние |
|---|---|
| Контрольная точка после каждого задания | реализовано |
| Кнопка «Следующее задание» без автоматического перехода | реализовано |
| Нельзя пропустить незаконченное задание | реализовано: кнопки «Пропустить задание» больше нет; выйти из задания можно только через «Пауза» → «Завершить занятие» |
| Пауза скрывает стимулы, время паузы не входит в задание | реализовано |
| После «Продолжить» прерванная проба повторяется | частично: задание начинается заново целиком, а не с прерванной пробы — игры не умеют останавливаться посреди пробы |
| Журнал пауз: задание, начало, конец, чем закончилась | реализовано |
| Статус abandoned | реализовано |
| Задание, которое не открылось, не останавливает занятие | реализовано: появляется «Следующее задание», задание получает статус «не показано» |
| Предельная длительность паузы | не реализовано: методика её не задаёт |
| Облегчённая альтернатива при прерывании из-за утомления | не реализовано |

## 10. Самочувствие до и после занятия

По решению от 29.09.2026 оценка самочувствия проводится **перед тренировочной
сессией и после неё** и в скрининг не входит.

| Правило | Состояние |
|---|---|
| Опросник: 6 вопросов, 3 блока, 5 состояний | реализовано: `GET /api/questionnaires/san` |
| Сохранение ответов с отметкой «до» или «после» | реализовано в ядре: `POST /api/questionnaires/san` |
| Опросник до и после занятия | не реализовано: на экране тренировки опросника нет |
| Опросник не входит в скрининг | расходится: в интерфейсе он стоит шагом базового скрининга после HADS, и ответы оттуда не отправляются |

## 11. Отчёты

**О занятии.** Пользователь видит, что занятие выполнено и сколько заданий
пройдено, без баллов по доменам. Специалист видит по каждому заданию форму,
уровень, стимульный набор, успешность, время, статус, переходы уровней,
отметки «трудная» и «потолок», паузы и прерывания, самочувствие до и после.

**О курсе.** Траектория уровня по каждой форме за 12 занятий; сравнение 6-го
и 12-го занятий только по формам, которые шли на одном уровне и на наборе 3;
регулярность; число прохождений форм-аналогов аудио-MoCA. Обязательная
подпись: «Тренировочная динамика отражает выполнение упражнений, а не
изменение когнитивного статуса».

| Правило | Состояние |
|---|---|
| Пользователю — номер занятия и число выполненных заданий | реализовано |
| Данные для отчёта специалиста: задания, уровни, наборы, успешность, статусы, паузы, переходы уровней | реализовано в ядре: `GET /api/training/course` |
| Экраны отчёта о занятии и о курсе | не реализовано |

## 12. Клинические границы

- Красные флаги — внезапное ухудшение речи или памяти, спутанность, очаговые
  симптомы — прекращение тренировки и направление к врачу. Модуль сам такие
  изменения не распознаёт; источник сигнала — пункт анкеты самочувствия.
- Результаты тренировок не используются для выводов о диагнозе.
- При падении успешности по нескольким формам разных доменов два занятия
  подряд специалист получает уведомление.

**Состояние: не реализовано.**

## 13. Расхождения со скринингом

Найдены при сверке с «Методологией скрининга» 2.0.

| Методология | Программа |
|---|---|
| HADS — ответы только кликом, без голоса (решение 29.09.2026) | у HADS есть голосовой ввод: ответ записывается и распознаётся |
| Повторение предложений — допускаются различия в окончаниях | оценка строго дословная, по устному решению методиста. Вопрос 8 методологии ещё открыт — нужно согласовать |
| Речевые показатели — исследовательские, пользователю не показываются, в отчёте специалиста с пометкой «исследовательский показатель, не для клинической интерпретации» | блок «Показатели речи» в отчёте без такой пометки, а отчёт сейчас видит и пользователь |
| Отметка «низкая достоверность» домена при 2 и более нераспознанных ответах | не реализовано |
| Отметка «интерпретировать с учётом тревоги / депрессии» при HADS ≥ 8 | не реализовано |
| Оценка самочувствия не входит в скрининг | стоит шагом базового скрининга |

## 14. Обращения к ядру

| Путь | Метод | Назначение |
|---|---|---|
| `/api/training/session` | GET | Текущее занятие курса: сохранённое или собранное заново |
| `/api/games/{code}/start` | POST | Запуск задания. Задание курса передаёт `{ "course_session": N, "course_position": P }`: уровень, набор и зерно ядро берёт из плана |
| `/api/training/session/pause` | POST | Пауза в журнал занятия: `{ "position": P }` или пусто между заданиями |
| `/api/training/session/resume` | POST | Конец паузы |
| `/api/training/session/finish` | POST | Завершение занятия, в том числе досрочное: `{ "reason": "…" }` |
| `/api/training/course` | GET | Курс целиком: занятия, исходы, уровни форм, журнал переходов |

Статусы задания в плане: `pending` — не начиналось, `started` — начато,
`done` — есть исход, `abandoned` — прервано, `not_presented` — занятие
закончилось раньше.
