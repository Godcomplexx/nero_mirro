# Тренировочный курс: как он формируется и работает

Описание по документу «Методика подбора и оценки тренировочного курса»,
черновик v2 от 08.10.2026, проект для утверждения. Входные данные курса
описаны в «Методологии скрининга», редакция 2.0 от 08.10.2026.

Обе методики ещё не утверждены. Значения с пометкой «предложение» —
предложения методики, а не утверждённые нормативы. В программе они заданы
константами в одном месте, чтобы после утверждения поменять их без переделки:
пороги перехода — `neuro_mirror/screening/difficulty_policy.py`, этапы и
стимульные наборы — `neuro_mirror/screening/training_course.py`.

У каждого правила указано состояние в программе:

- **реализовано** — работает так, как написано;
- **частично** — работает, но не полностью или иначе;
- **не реализовано** — в программе этого пока нет.

## 1. Место курса в цикле наблюдения

Курс стоит между входным и выходным скринингом:

1. **Входной скрининг** — подготовка сессии, базовый скрининг (видеоанализ и
   HADS) и расширенный скрининг (аудио-MoCA, затем ситуационная задача).
2. **Курс тренировок** — 12 занятий.
3. **Выходной скрининг** — те же пробы в том же порядке. Ситуационная задача
   проводится на парном нарративе, а не на том, что был на входе.

Динамику когнитивного статуса показывает только выходной скрининг. Результаты
тренировок отражают выполнение упражнений.

| Правило | Состояние |
|---|---|
| Курс открывается после завершённого входного скрининга, до этого тренировка заблокирована с текстовой причиной | реализовано |
| После 12-го занятия курс закрывается, следующий шаг — выходной скрининг | реализовано: тренировка отвечает «Курс из 12 занятий пройден…» и предлагает пройти когнитивный тест. Результат теста, полученный после закрытия курса, начинает новый курс |
| Ситуационная задача | не реализовано: методика модуля на утверждении |

## 2. Вход курса

Модуль тренировок получает от агрегатора результат аудио-MoCA по четырём
доменам: память 0–5, внимание 0–5, речь 0–3, абстракция 0–2, сумма 15.

Из баллов получаются два показателя с разным назначением:

- **недобор** `U = M − S` — по нему распределяются задания;
- **нормированный дефицит** `D = (M − S) / M` — идёт в отчёт специалиста,
  чтобы сравнивать домены с разными максимумами.

Здесь `S` — балл пользователя, `M` — максимум домена.

Недобор фиксируется по **входному** скринингу на весь курс. Результаты
тренировок его не пересчитывают: иначе тренировка подменила бы обследование.

| Правило | Состояние |
|---|---|
| Недобор и нормированный дефицит по четырём доменам | реализовано |
| Недобор фиксируется по входному скринингу на весь курс | реализовано: профиль запоминается при открытии курса; тест, пройденный во время курса, его не меняет |
| Домен с отметкой «низкая достоверность» (2 и более нераспознанных ответа) получает недобор 0 до подтверждения специалистом | частично: отметка ставится и видна в отчёте специалиста (`screening/data_quality.py`), но на состав курса пока не влияет — нет подтверждения специалистом, а состав курса по решению команды постоянен на 12 занятий |
| Контекст HADS: при 8 баллах и выше по любой подшкале — отметка рядом с результатом аудио-MoCA | не реализовано |

Исполнительные функции относятся к домену «Абстракция»: аудио-MoCA не даёт по
ним отдельного балла, поэтому доменов четыре.

## 3. Структура курса

**Как формируется курс.** Курс составляется по входному скринингу сразу на
все 12 занятий — 12 слотов. Состав по доменам (например, 4 задания на память,
2 на внимание, 2 на речь, 2 на абстракцию) **во всех 12 занятиях одинаков**.
От занятия к занятию меняются:

- **формы** — подбираются при открытии каждого занятия и чередуются по
  приоритетам методики (раздел 8.3);
- **уровень сложности каждой формы** — по правильности её прохождений
  (раздел 6);
- **стимульный набор** — по этапу курса (раздел 8.5).

Человек сам игры не выбирает. «Выбрать игру самому» — дополнительная
возможность для проверки игр и для врача; такая игра в курс не входит и
уровни не меняет.

- 12 занятий по 10 заданий, всего 120 прохождений.
- Одно задание — около 5 минут, занятие — около 50 минут.
- Частота — 2 занятия в неделю, курс — около 6 недель.
- В каждом занятии 4 обязательных задания, по одному на домен, и 6
  дополнительных — по недобору.

| Правило | Состояние |
|---|---|
| Занятие из 10 заданий, длина задаётся параметром, не меньше 4 | реализовано |
| Курс из 12 занятий с номером занятия | реализовано: 12 слотов создаются сразу при открытии курса |
| Состав по доменам одинаков во всех 12 занятиях | реализовано |
| Формы чередуются от занятия к занятию | реализовано |
| Частота 2 занятия в неделю | не контролируется: следующее занятие доступно сразу после завершения предыдущего |

## 4. Распределение заданий по доменам

1. Каждый домен получает по одному заданию — 4 из 10.
2. Остальные 6 раздаются по одному. Каждое следующее получает домен с
   наибольшим отношением `U / n`, где `n` — сколько заданий у домена уже есть.
3. Потолок — не больше половины занятия на один домен. Домен, достигший
   потолка, из раздачи выбывает.
4. При равенстве отношений первым идёт домен, у которого меньше заданий.
   При полном равенстве — фиксированный порядок: память, внимание, речь,
   абстракция.
5. Сравнение точное, перекрёстным умножением, без округления.

Контрольные случаи из методики. Все шесть проверены на коде и совпадают:

| Случай | Недобор: память / внимание / речь / абстракция | Длина | Результат |
|---|---|---|---|
| Пример 1 | 2 / 1 / 1 / 1 | 10 | 4 / 2 / 2 / 2 |
| Пример 2 | 3 / 1 / 0 / 1 | 10 | 5 / 2 / 1 / 2 |
| Недобора нет | 0 / 0 / 0 / 0 | 10 | 3 / 3 / 2 / 2 |
| Потолок памяти | 5 / 0 / 0 / 0 | 10 | 5 / 2 / 2 / 1 |
| Только абстракция | 0 / 0 / 0 / 2 | 10 | 2 / 2 / 1 / 5 |
| Длина 9 | 5 / 0 / 0 / 0 | 9 | 4 / 2 / 2 / 1 |

| Правило | Состояние |
|---|---|
| Обязательный минимум, пошаговая раздача, потолок | реализовано |
| Равенство: меньше заданий, затем фиксированный порядок | реализовано |
| Равенство: домен, реже встречавшийся в курсе | не применяется: состав считается один раз на весь курс и между занятиями не меняется. Методика допускает здесь чередование троек при полном балле — решение команды: состав постоянный |

## 5. Этапы курса

| Занятия | Этап | Назначение | Уровни |
|---|---|---|---|
| 1–2 | Калибровка | Понимание инструкций, работа интерфейса, знакомство с формами | Уровень 1 у всех форм |
| 3–5 | Освоение | Стабилизация, основная нагрузка на приоритетные домены, накопление динамики по каждой форме | Уровень 1 у всех форм; уровни не меняются |
| 6 | Присвоение уровней и промежуточный контроль | Уровни присваиваются по динамике занятий 3–5; проверка устойчивости на новом стимульном наборе | Уровень 1 или 2 |
| 7–12 | Адаптивная тренировка | Удержание успешности 70–85% и рост сложности; в 12-м занятии — стимульный набор 3 для сравнения с 6-м | Уровни меняются по итогам предыдущего занятия, до уровня 3 |

После 12-го занятия собираются итоговые показатели и проводится выходной
скрининг.

**Состояние: реализовано.** Номер занятия задаёт этап, стимульный набор и то,
меняются ли уровни. Этап и номер приходят в ответе
`GET /api/training/session` (`course.session_number`, `course.stage`) и
показываются на экране тренировки: «Занятие 3 из 12 · Освоение».

## 6. Уровень сложности

Уровень ведётся отдельно для каждой формы у каждого пользователя. Переход по
одной форме не меняет уровни других форм того же домена.

### 6.1. Какие прохождения учитываются

| Статус завершения | Учитывается для адаптации |
|---|---|
| completed_success — правильный ответ до исчерпания времени и попыток | да |
| completed_unsuccessful — попытки исчерпаны | да |
| timeout — лимит времени | да |
| abandoned — пользователь прервал | нет: нулём не считается |
| technical_invalid — техническая проблема | нет |
| «не определено» — у формы нет показателей полноты | нет: форма идёт без адаптации |

Успешность хранится как числитель и знаменатель. Порог проверяется точно:
`правильные · 100 ≥ 85 · всего`.

В программе статус U06 рассчитывается по показателям игры
(`plugins/games/base.py`, `u06_status`) и пишется в отчёт прохождения и в план
занятия: `completed_success`, `completed_unsuccessful` (попытки исчерпаны:
сейчас так кончается GM-02 — первая ошибка завершает задание), `timeout`
(лимит времени: GM-01 и GM-10), `technical_invalid` или `undetermined`.
Статус `abandoned` ставит курс: игра о прерывании не узнаёт. Учитываются
первые три. Облегчённая альтернатива (раздел 9) идёт на временном уровне и
не учитывается.

### 6.2. Правило перехода

| Успешность прохождения | Условие | Действие при следующем показе формы |
|---|---|---|
| не меньше 0,85 | одно учитываемое прохождение | уровень +1 |
| от 0,50 до 0,85 | — | уровень сохраняется |
| меньше 0,50 | два учитываемых прохождения подряд | уровень −1 |

Счётчик «ниже 50% подряд» ведётся по форме и сбрасывается при любой смене
уровня. За один пересчёт уровень меняется не больше чем на один шаг.
Неучитываемые прохождения серию не прерывают и в неё не входят.

### 6.3. Когда применяется правило

1. **Занятия 1–5** — у всех форм уровень 1, уровни не меняются.
2. **Перед 6-м занятием** уровень присваивается по занятиям 3–5. Предложение:
   уровень 2, если сводная успешность формы за занятия 3–5 не ниже 0,85, а
   последнее прохождение не ниже 0,70. Иначе уровень 1. При сводной
   успешности ниже 0,50 форма получает отметку «трудная».
3. **Занятия 7–12** — уровни пересчитываются по итогам предыдущего занятия.
   Если форма в нём не показывалась, её уровень не меняется.
4. **После 12-го занятия** уровни не пересчитываются.

Граничные случаи (предложение): ниже 50% дважды подряд на уровне 1 — уровень
остаётся 1, форма получает отметку «трудная». 85% и выше на уровне 3 —
уровень остаётся 3, отметка «потолок».

### 6.4. Как это устроено в программе

**Состояние: реализовано.**

- Уровни не хранятся отдельно, а выводятся из прохождений курса при сборке
  каждого занятия (`training_course.form_states`). Сохранённое состояние не
  может разойтись с тем, что человек проходил.
- Сводная успешность за занятия 3–5 — сумма верных на сумму всех, а не
  среднее долей.
- Отметки «трудная» и «потолок» идут в план занятия (`flags`) и в отчёт
  специалиста. Генератор выбирает такие формы реже: только когда других
  форм домена не осталось (раздел 8.3).
- Каждый переход записывается в журнал: перед каким занятием, форма, с какого
  уровня на какой, по какой успешности. Переходы перед текущим занятием
  приходят в `level_changes` ответа `GET /api/training/session`, весь журнал —
  в `GET /api/training/course`.
- Игра, открытая через «Выбрать игру самому» (проверка, врач), в курс не
  входит и уровни не меняет.

## 7. Формы, готовые к адаптации

Уровни 1–3 есть у всех 24 форм (`neuro_mirror/plugins/games/game_levels.json`,
таблица — [game-levels.md](game-levels.md)). У 12 форм значения из матрицы игр,
у остальных 12 — предварительные (`draft`): в матрице их нет, они используются
на апробации. Курс меняет уровень у 13 форм ниже: у 12 уровни утверждены и
есть показатель успешности по методике, GM-05 добавлена решением команды
(см. ниже). Остальные идут на уровне 1 без адаптации.

| Домен | Формы, у которых курс меняет уровень |
|---|---|
| Память | GM-01, 02, 03, 04, 05, 06 |
| Внимание | GM-07, 09, 10 |
| Речь | GM-14 |
| Абстракция | GM-17, 18, 22 |

Значения уровней совпадают с матрицей, кроме GM-07: игра работает на сетках
4×4, 8×8, 10×10 (16, 64, 100 объектов), а в матрице — 10, 15, 20 объектов.
Расхождение нужно уточнить у методистов.

Показатель успешности для перехода — числитель и знаменатель:

| Форма | Показатель по методике | Верные / всего в программе |
|---|---|---|
| GM-01 | U08 — доля найденных пар | найденные пары / все пары |
| GM-02 | M08 — доля полностью верных серий | верные серии / все серии |
| GM-03 | U01 | верные пробы / все пробы |
| GM-04 | M07 | узнанные цели / все цели |
| GM-05 | M07 при контроле G08; в методике «готовность к адаптации — нет» | **верные решения / все слова списка**: узнанные старые + не отмеченные новые |
| GM-06 | M08 | верные серии / все серии |
| GM-07 | U01 | верные экраны / все экраны |
| GM-09 | A06 — доля правильно выбранных целей | выбранные цели / все цели |
| GM-10 | A07 — доля найденных отличий | найденные отличия / все отличия |
| GM-14 | U01 — слова, собранные с первой попытки | слова с первой попытки / все слова |
| GM-17 | U01 | верные пробы / все пробы |
| GM-18 | U01 — фрагменты, установленные с первой попытки | фрагменты, вставшие на место первым же перемещением / все перемещённые фрагменты |
| GM-22 | U03 — доля башен, собранных в целевую конфигурацию | собранные башни / все башни |

GM-02 раньше оценивалась по последней серии: ошибка на десятой серии давала
ноль. Теперь — по всем сериям прохождения, как в методике.

**GM-05 — решение команды, отступление от методики.** Доля узнанных слов
(M07) для смены уровня не годится: отметив все слова подряд, человек получил
бы 100%. Поэтому считаются верные решения по каждому слову: отметил старое
или не отметил новое. Угадывание даёт около 50%, точное узнавание — 100%.
Уровни GM-05 предварительные (`draft`). Формулу и уровни нужно согласовать с
методистами. Примеры на уровне 1 (4 старых и 4 новых слова): ровно 4 старых —
8/8, уровень вверх; 3 старых и 1 новое — 6/8, уровень сохраняется; всё подряд
или ничего — 4/8, уровень не повышается.

**Лимит времени GM-01 и GM-10 — предложение команды.** Методика пишет «в
лимите времени» (GM-01) и «за фиксированное время» (GM-10), а значения
оставляет на утверждение. В программе лимит на задание целиком: GM-01 —
240 / 240 / 300 с по уровням, GM-10 — 450 / 480 / 450 с (около 90, 120 и
150 с на сцену). Значения в `game_levels.json` (`time_limit`, статус `draft`),
таблица — в [game-levels.md](game-levels.md). Время считает ядро, по активному
времени: пауза не входит, время прерванной пробы после паузы отбрасывается.
Оставшееся время на экране не показывается (`visible: false`): таймер на
экране добавим, если методисты подтвердят, что он не добавляет стресса.

**Вопрос к методистам.** У GM-22 лимита времени нет, задание заканчивается
только сборкой. Поэтому законченное прохождение всегда даёт 100%, и с 7-го
занятия уровень растёт при каждом показе. Правила GM-22 методика оставляет
на утверждение.

| Правило | Состояние |
|---|---|
| 12 форм с уровнями, значения из матрицы | реализовано, кроме GM-07 (см. выше) |
| Уровни остальных 12 форм | предварительные (`draft`), курс их не меняет |
| Отметка fixed_config у форм без уровней | реализовано: у таких форм `adaptation: "fixed_config"` и пустой уровень |
| Показатель успешности по методике у всех 12 форм | реализовано |
| Адаптация GM-05 | реализовано по решению команды; согласовать с методистами |

## 8. Сборка занятия

### 8.1. Обязательные правила

1. Состав по доменам — по разделу 4, все четыре домена представлены.
2. Одна форма не повторяется дважды в одном занятии.
3. Тренировочные формы не копируют материалы аудио-MoCA (GM-11, 13, 16, 24).

### 8.2. Желательные правила, по убыванию веса

1. Не больше трёх подряд заданий с одинаковым типом ответа.
2. Не больше трёх подряд с одинаковой визуальной схемой выбора.
3. После сложного задания — более простое или другое по модальности.
4. Два задания одного домена не стоят подряд.
5. Модальности подачи чередуются.

Порядок заданий строит `screening/session_order.py`. Из всех порядков
подобранных форм берётся порядок с наименьшим взвешенным числом нарушений; при
равенстве решает зерно занятия «пользователь + номер занятия». Числовых весов
методика не задаёт, только порядок; в программе веса 5, 4, 3, 2, 1 — решение
команды. Каждое нарушение выбранного порядка пишется в план (`order.violations`)
и показывается специалисту.

- «Сложное» задание — уровень 3 или успешность ниже 0,50 в прошлый раз.
- Правило 2 не проверяется: в каталоге игр нет признака «схема выбора». В плане
  оно записано как непроверенное (`order.not_checked`).
- Правило 1 на нашем наборе часто невыполнимо: из 13 адаптивных форм 11
  отвечаются кликом (вопрос 1 методики). Поэтому порядок не бракуется, а
  нарушение записывается.
- Закреплены места: калибровка начинается с формы «клик и зрительная подача»
  (5.2, п. 4); с 3-го занятия первое и последнее задания — формы с наибольшей
  недавней успешностью (последнее учитываемое прохождение формы в курсе).

### 8.3. Выбор формы внутри домена

Формы подбираются при открытии каждого занятия по порядку приоритета
(разделы 4.4, 5.2, 6.3):

1. форма с уровнями сложности, готовая к адаптации (формы без адаптации
   берутся, когда домену не хватает адаптивных);
2. форма без отметок «трудная» и «потолок»;
3. механика, реже встречавшаяся в курсе;
4. форма, которой не было в прошлом занятии;
5. механика и модальность отличаются от предыдущего задания занятия;
6. меньше прошлых показов.

За счёт пунктов 3 и 4 за калибровку (занятия 1–2) охватываются все
адаптивные формы, а дальше формы чередуются. Уровень каждой формы
переходит из занятия в занятие: форма, которой в занятии не было, сохраняет
уровень до следующего показа (раздел 6.3).

Пример для состава 4/2/2/2: память в 1-м занятии — GM-01, 02, 03, 04, во
2-м — GM-05, 06, 01, 02, в 3-м — GM-03, 04, 05, 01. Речь: GM-14 — единственная
адаптивная форма речи, она идёт в каждом занятии; второе задание речи
чередуется между формами без адаптации (GM-12, 13, 15, 16).

### 8.4. План занятия

12 слотов создаются при открытии курса. Формы, порядок, уровни, стимульные
наборы и зёрна ставятся в слот, когда занятие открывается, — они зависят от
предыдущих занятий; дальше план не меняется (кроме облегчённой альтернативы,
которая встаёт сразу за прерванным заданием). Перезагрузка страницы и возврат к прерванному занятию берут
сохранённый план. Хранится в `runtime/deidentified/training_courses.json`.

### 8.5. Стимульные наборы

| Занятия | Набор |
|---|---|
| 1–2 | набор 1 |
| 3–5 | набор 2 |
| 6 | набор 3, ранее не показанный |
| 7–11 | наборы 1 и 2 по очереди |
| 12 | набор 3, для сравнения с 6-м |

Номер набора соответствует порядку наборов формы в матрице. У формы с одним
набором он показывается всегда, а различаются занятия зерном случайности
«пользователь + форма + номер занятия». Игры курса перемешивают стимулы этим
зерном: повторный запуск того же задания даёт те же стимулы. Свободная игра
зерна не получает и перемешивает случайно.

## 9. Ход занятия

- После каждого задания сохраняется контрольная точка.
- Задание заканчивается досрочно, по лимиту времени или по исчерпанию
  попыток. Затем — экран с нейтральной обратной связью и кнопкой «Следующее
  задание». Автоматического перехода нет.
- Кнопка «Пауза» доступна всегда. На паузе таймер останавливается, стимулы
  скрываются. Из паузы — «Продолжить», «Прервать задание» или «Завершить
  занятие».
- После «Продолжить» прерванная проба предъявляется заново и не оценивается,
  выполненные пробы задания сохраняются. Что такое проба, решает игра: экран,
  раунд, слово, пазл. У форм памяти — с нового предъявления: GM-01
  перекладывает доску, GM-03 и GM-04 снова показывают материал для
  запоминания. Так же задание продолжается после перехода в другой раздел и
  перезагрузки страницы. Если ядро перезапускали и игровой сессии нет,
  задание начинается заново.
- Прерванное задание получает статус abandoned: нулём не считается и в
  адаптацию не входит. Причина записывается: устал(а), плохое самочувствие,
  задание слишком трудное, новые или необычные симптомы, другая причина.
- При утомлении или плохом самочувствии первым предлагается завершить
  занятие. Иначе — облегчённая альтернатива: та же форма уровнем ниже, а на
  уровне 1 — другая форма того же домена на уровне 1. Альтернатива встаёт
  сразу за прерванным заданием; её уровень временный, в адаптацию она не
  входит. Если облегчить нечем, можно перейти к следующему заданию.
- «Завершить занятие» тоже спрашивает причину; она пишется брошенному
  заданию и в окончание занятия.
- Время паузы и время до нажатия «Следующее задание» не входят в активное
  время.
- Каждая пауза пишется в журнал: задание, проба, начало, конец, чем
  закончилась.

| Правило | Состояние |
|---|---|
| Контрольная точка после каждого задания | реализовано |
| Кнопка «Следующее задание» без автоматического перехода | реализовано |
| Нельзя пропустить незаконченное задание | реализовано: кнопки «Пропустить задание» больше нет; выйти из задания можно только через «Пауза» → «Завершить занятие» |
| Пауза скрывает стимулы, время паузы не входит в задание | реализовано |
| После «Продолжить» прерванная проба повторяется | реализовано во всех 24 играх |
| Журнал пауз: задание, проба, начало, конец, чем закончилась | реализовано |
| Лимит времени и статус timeout | реализовано у GM-01 и GM-10 (значения — предложение команды) |
| Статус abandoned | реализовано |
| Задание, которое не открылось, не останавливает занятие | реализовано: появляется «Следующее задание», задание получает статус «не показано» |
| Предельная длительность паузы | не реализовано: методика её не задаёт |
| Причина прерывания записывается | реализовано |
| При утомлении сначала предлагается завершить занятие | реализовано |
| Облегчённая альтернатива, временный уровень | реализовано |

По решению от 29.09.2026 оценка самочувствия проводится **перед тренировочной
сессией и после неё** и в скрининг не входит.

| Правило | Состояние |
|---|---|

| Опросник до и после занятия | реализовано: перед первым заданием и после завершения занятия, в том числе досрочного; ответы связаны номером занятия курса, опрос можно пропустить |

## 11. Отчёты

**О занятии.** Пользователь видит, что занятие выполнено и сколько заданий
пройдено, без баллов по доменам. Специалист видит по каждому заданию форму,
уровень, стимульный набор, успешность, время, статус, переходы уровней,
отметки «трудная» и «потолок», паузы и прерывания, самочувствие до и после.

**О курсе.** Траектория уровня по каждой форме за 12 занятий; сравнение 6-го
и 12-го занятий только по формам, которые шли на одном уровне и на наборе 3;
регулярность; число прохождений форм-аналогов аудио-MoCA. Обязательная
подпись: «Тренировочная динамика отражает выполнение упражнений, а не
изменение когнитивного статуса».

| Правило | Состояние |
|---|---|
| Пользователю — номер занятия и число выполненных заданий | реализовано |
| Данные для отчёта специалиста: задания, уровни, наборы, успешность, статусы, паузы, переходы уровней | реализовано в ядре: `GET /api/training/course` |
| Отчёт о занятии (8.2) | реализовано в отчёте специалиста («Отчёты» → «Для специалиста», по PIN): по каждому заданию форма, уровень (временный — с пометкой), набор, успешность, статус U06, активное время, досрочное выполнение (у заданий с лимитом), причина прерывания; паузы с пробой и длительностью; самочувствие до и после этого занятия; вопрос о симптомах; нарушения порядка |
| Отчёт о курсе (8.3) | реализовано там же: траектория уровня каждой формы по 12 занятиям, сравнение 6-го и 12-го (только на одном уровне и на наборе 3, по остальным — причина), регулярность, число прохождений GM-11, 13, 16, 24, нормированный дефицит D, подпись |
| Оговорка об эффекте научения в динамике | реализовано: если балл домена аудио-MoCA вырос, а в курсе проходились формы с механикой аудио-MoCA этого домена, в «Динамике» стоит оговорка |

## 12. Клинические границы

- Красные флаги — внезапное ухудшение речи или памяти, спутанность, очаговые
  симптомы — прекращение тренировки и направление к врачу. Модуль сам такие
  изменения не распознаёт. Источники сигнала: вопрос перед каждым занятием
  («За последние дни вы замечали внезапное ухудшение памяти или речи,
  спутанность или другие новые необычные симптомы?») и причина прерывания
  «новые или необычные симптомы». Формулировка вопроса — черновик команды
  (`screening/training_safety.py`): её утверждают методисты с неврологом
  (вопрос 2 методики).
- При красном флаге занятие не начинается или завершается, пользователю
  рекомендуется обратиться к врачу, курс приостанавливается. Снять
  приостановку может только специалист в своём отчёте. Занятие, остановленное
  вопросом перед началом, не расходуется.
- Результаты тренировок не используются для выводов о диагнозе.
- Уведомления специалисту — вверху его отчёта: красные флаги и приостановка
  курса; больше двух неполных занятий; все адаптивные формы домена с
  отметкой «трудная»; устойчивое падение успешности. Падение — три
  учитываемых прохождения формы подряд на одном уровне, каждое ниже
  предыдущего, последнее — в одном из двух последних занятий; уведомление —
  когда так падают хотя бы две формы двух разных доменов. Пороги — предложение
  методики, константы в `screening/course_report.py`.

| Правило | Состояние |
|---|---|
| Вопрос о новых симптомах перед занятием | реализовано; формулировка — черновик |
| Красный флаг: остановка, совет обратиться к врачу, приостановка курса | реализовано |
| Уведомления специалисту | реализовано: в отчёте специалиста, без отдельной рассылки |

## 14. Обращения к ядру

| Путь | Метод | Назначение |
|---|---|---|
| `/api/training/session` | GET | Текущее занятие курса. В `course.slots` — все 12 слотов с этапом и состоянием |
| `/api/games/{code}/start` | POST | Запуск задания. Задание курса передаёт `{ "course_session": N, "course_position": P }`: уровень, набор и зерно ядро берёт из плана |
| `/api/games/{code}/resume` | POST | Продолжение задания с прерванной пробы: `{ "session_id": "…", "course_session": N, "course_position": P }`; 409 — продолжить нельзя, задание начинается заново |
| `/api/training/session/pause` | POST | Пауза в журнал занятия: `{ "position": P, "game_code": "…", "game_session_id": "…" }` или пусто между заданиями; ядро узнаёт у игры номер пробы |
| `/api/training/session/resume` | POST | Конец паузы |
| `/api/training/session/interrupt` | POST | Прервать задание с причиной: `{ "position": P, "reason": "fatigue" }`; ответ — что предложить: завершить занятие или облегчённую альтернативу; при красном флаге — остановка |
| `/api/training/session/alternative` | POST | Поставить облегчённую альтернативу за прерванным заданием: `{ "position": P }` |
| `/api/training/session/check` | POST | Ответ на вопрос о новых симптомах перед занятием: `{ "new_symptoms": false }` |
| `/api/training/session/finish` | POST | Завершение занятия, в том числе досрочное: `{ "reason_code": "fatigue" }` |
| `/api/training/course` | GET | Курс целиком: занятия, исходы, уровни форм, журнал переходов |
| `/api/specialist/course/release` | POST | Специалист снимает приостановку курса после красного флага (по PIN) |

Если курс приостановлен, `GET /api/training/session` отвечает 409 с заголовком
`X-Course-Hold: 1`.

Статусы слота: `planned` — ещё не открыт, `in_progress` — идёт,
`completed` — все задания выполнены, `incomplete` — завершён досрочно.

Статусы задания в плане: `pending` — не начиналось, `started` — начато,
`done` — есть исход, `abandoned` — прервано, `not_presented` — занятие
закончилось раньше.
